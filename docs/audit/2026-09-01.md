## 2. The efficacy findings, in order of how much they matter

### 2.1 A piece the artist called a failure scores 1.0 / 1.0

`out/openai-withheld/final.json` — one of only **two completed real-model runs in the entire repo**:

```
outcome: finished     tree: 1     render: 1     hardViolations: 0     softViolations: 0
selfScore: 4/10
termination: { kind: "out-of-steps", legitimate: false,
               edgesUnrealized: 6, unrealizedEdges: [6 relations that did not hold] }
```

A perfect score sits beside `legitimate: false`, a self-score of 4, and six of the artist's own
planned relations not landing. **The headline number is uncorrelated with whether the work is any
good, and the fields that say so are two levels down.**

It is not one run. Every scored run on disk, read back from `final.json`:

| run | tree | render | realization | legitimate | termination |
|---|---|---|---|---|---|
| `condition-withheld` | **1** | **1** | **0** | false | finish-blocked |
| `openai-withheld` | **1** | **1** | **0** | false | out-of-steps |
| `overnight-plumbing-withheld` | 0.6 | 0.2 | 1 | false | finish-blocked |

**Not one run in this repository has ever legitimately finished**, and the two that score a perfect
1.0 / 1.0 are the two whose `realization.score` is **0** — zero of the artist's own planned relations
held. The summary score is not merely uninformative here; on the only two real-model runs that exist
it is anticorrelated with the one number that tracks whether the plan was carried out.

Confirmed live in the studio run list, which prints `tree 1.000 render 1.000 hard 0` for both.

`run.ts:678` already fixed the *outcome* word for exactly this reason. The *scores* were not fixed.
`tree` and `render` are means over constraint results; they saturate at 1.0 the moment the
hand-written rules are satisfied, and the hand-written rules are mostly node counts.

**Obvious fix:** `scores.tree`/`scores.render` should be reported as `null` — or carry an explicit
`legitimate: false` flag — when `termination.legitimate` is false. A run that did not earn its stop
does not have a score.

### 2.2 The only constraints that ask an artistic question are never decided

From the traced checker output, `withheld` carries 13 constraints:

- **9 tree-counting** — `requireNode` ×3, `requireMark`, `maxRepeatDepth`, `textMaxWords`,
  `textMinHeight`, `forbidMark`, `nodeCount`. These count nodes in a JSON tree.
- **3 pixel-measured** — `inkDensityRange`, `edgeContactRange`, `inkOffsetRange`. Real render metrics.
- **2 `rubric`** — `j-necessity`, `j-only-this`. These are the position's actual subject:

  > *"take each covered region and ask whether anything visible on the sheet constrains what could
  > have been underneath it. If the coverings could be slid two centimetres in any direction without
  > changing a single relationship, then nothing was ever under them, the withholding is a shape, and
  > the piece is a composition of dark rectangles claiming to be a refusal."*

Every step of every run, both rubrics report:

```
undecided  [j-necessity] rubric (hard) judge scope: no judge in this layer, returned unread
```

`out/condition-withheld/final.json` ships `pendingRubrics` with both of them still pending. **No
`judge.json` exists in any run directory.** `artist judge <dirs>` exists (`artist/judge.ts`, 485
lines, three offline critics) but `run.ts` never calls it and nobody has run it since the L3
deletion — `out/judgment.json` still carries `deliverableId: "panel"`, a field from a subsystem
deleted at `aced259`.

The observation is honest about this — *"'undecided' is not a pass. It means nobody checked."* — but
the artist is being graded, in the loop, exclusively on the constraints that a node count can
settle, and the two that ask whether the piece means anything are structurally unreachable.

**This is the single largest gap between the machinery and the mission.** The judge is written, and
as of 14:59 today it is repointed to `claude-opus-4-6` with its guard test updated (§0b) — so it is
also *ready*. It is still not wired: `run.ts` contains no reference to it.

**Obvious fix:** call the judge once, at EXAMINE, on the rubrics only, and let a violated hard rubric
be a `finishBlockers` entry. That is a ~30-line change to `run.ts` + `gate.ts` and it converts the
most artistically-loaded constraints from decoration into a stopping rule. Cost: one extra model
call per finish attempt.

### 2.5 70% of "THE PROGRAM AS IT STANDS" is a redundant edit log

`observation.ts:513` and `:596` do `json(c.program)` — `JSON.stringify(program, null, 2)`, whole.
The program carries `meta.provenance`, an append-only edit history written by `env/edits.ts:122`
that stores a **full copy of every inserted node, twice** (`before` and `after`).

Measured on `out/openai-withheld/final.json`:

```
final program JSON:   37,821 chars
  meta.provenance:    26,432 chars  =  69.9%
```

That block is in every `act` and every `replan` observation, growing monotonically — the traced run's
`act` observation went 32,575 → 40,072 chars across 8 steps, and the growth is almost entirely
provenance. The artist is **also** given the same history, in prose, in `WHAT YOU HAVE DONE`.

So roughly 7K tokens per late-stage MAKE call is duplicated JSON sitting between the plan and the
checker table. It is not just cost; it is the noisiest thing in the prompt.

**Obvious fix:** strip `meta` from the program before serialising it into the observation. One line.

**But:** `observation.ts` is byte-hashed into `OBSERVATION_HASH`, so this moves `envVersion` and
retires `out/openai-withheld` / `out/condition-withheld` as drift-comparable against the current
tree. Given there are only two real runs and both are already `legitimate: false`, that is probably a
price worth paying — **but it is your call, not mine.** Do it in the same commit as 2.2 if you do it,
so the hash moves once.

### 2.6 `problemsGrounded: 0 / 3`

FIND requires every problem to quote the field, and `grounded()` (`phases/find.ts:101`) only counts a
quote of **eight or more words** that appears verbatim in the field text. The traced run scored 0/3
and so does the stub by construction. Worth confirming on a real run before treating the eight-word
rule as calibrated — `find.ts:84-94` already documents one case where this measurement reported the
exact opposite of what happened.
